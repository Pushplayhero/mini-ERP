## 1. Overview

`v0.2.0-platform` marks the completion of **Phase 2 (Weeks 9–13)** of the `mini-erp` master plan. Building on top of the Phase 1 Order-to-Cash (`O2C`) kernel (`v0.1.0`), this release delivers five modular, tenant-isolated platform capabilities—identity & RBAC, tenant-governed plugins, runtime custom fields, multi-level Separation-of-Duties (SoD) approval workflows, and webhook/batch external integration—without introducing cross-module imports or bypassing core accounting invariants.

## 2. Highlights by Platform Module

### 2.1 `platform.permissions` — Identity, Multi-Company Sessions & RBAC ([ADR-009](file:///c:/Users/A275/Desktop/mini-ERP-main/docs/adr/ADR-009-platform-permissions.md))
- **Authentication & Company Scoping**: Server-side opaque bearer sessions (`sessions` table storing SHA-256 token digests) with `POST /auth/login`, `POST /auth/switch-company`, and `POST /auth/logout`, `pwdlib` Argon2 password hashing, and active `ActorContext` resolution in `AuthenticationMiddleware`.
- **Fail-Closed Authorization**: 55 canonical permissions (`module.resource.action`) mapped to tenant-scoped roles (`roles`, `role_permissions`, `user_company_roles`). Startup validation (`_classify_routes_or_crash`) crashes on boot if any route omits explicit `Public()`, `Authenticated()`, or `RequiresPermission(code)` classification.
- **CLI-Only Privileged Provisioning**: Moved global UoM/currency/exchange-rate writes and tenant company creation off HTTP to `app.cli.manage_reference_data`, `app.cli.manage_companies`, and `app.cli.bootstrap_admin`.

### 2.2 `platform.plugins` — Tenant-Scoped Plugins & Manifest Registry ([ADR-010](file:///c:/Users/A275/Desktop/mini-ERP-main/docs/adr/ADR-010-platform-plugins.md))
- **Runtime Registry & Tenant Persistence**: Per-company `company_plugins` state (`is_enabled`, JSONB `config`) exposed via `GET /api/v1/plugins` and `GET/PATCH /api/v1/plugins/{plugin_name}`, plus `app.cli.manage_plugins`.
- **Topological Ordering & Hook Gating**: Deterministic DAG ordering (`requires`) on plugin manifests and fail-closed hook filtering in `app/core/hooks.py` respecting the active tenant's enablement state.
- **Built-in `credit_limit` Governance**: Upgraded to declarative `PluginManifest` with 6-decimal-place `ROUND_HALF_EVEN` `grace_amount`, checking uninvoiced confirmed/shipped orders plus open AR exposure on `sales_order.confirm` (`409 Conflict` when exceeded).

### 2.3 `platform.customfields` — Dynamic Metadata Validation ([ADR-011](file:///c:/Users/A275/Desktop/mini-ERP-main/docs/adr/ADR-011-platform-customfields.md))
- **Schema Engine**: Supports 6 typed fields (`TEXT`, `INTEGER`, `DECIMAL`, `BOOLEAN`, `DATE`, `ENUM`) across 8 entities (`customer`, `product`, `account`, `accounting_period`, `journal_entry`, `sales_order`, `invoice`, `payment`) at `/api/v1/custom-fields`.
- **Financial Precision & Strict Validation**: Quantizes `DECIMAL` values via Banker's Rounding to 6 decimal places, validates `min_value`/`max_value`/`min_length`/`max_length`/`regex`/`min_date`/`max_date`/`choices`, populates defaults on create, and rejects unknown or malformed keys with `422 Unprocessable Entity`.
- **Safe Lifecycle**: Soft deactivation (`DELETE /api/v1/custom-fields/{id}`) disallows new writes to retired keys while preserving historical `custom_data` on existing records.

### 2.4 `platform.workflow` — Multi-Level Approval & SoD Engine ([ADR-012](file:///c:/Users/A275/Desktop/mini-ERP-main/docs/adr/ADR-012-platform-workflow.md))
- **Threshold-Routed Steps**: Configurable definitions (`/api/v1/workflows/definitions`) and execution instances (`/api/v1/workflows/instances`) guarding `sales_order.confirm`, `sales_order.cancel`, `invoice.void`, `payment.void`, and `journal_entry.reverse`.
- **Separation of Duties & Step RBAC**: Enforces `allow_self_approval=False` (requester cannot approve own submission -> `403 Forbidden`) and per-step `required_permission` validation (`403 Forbidden` if an approver lacks the target step's privilege).
- **Concurrency & Anti-Replay**: Serializes approval steps with `SELECT ... FOR UPDATE`, snapshots step policies on submission with policy-tightening parity checks at gate verification, enforces partial unique active index `uq_workflow_instance_active`, and atomically marks approved instances `CONSUMED` inside the business state-transition transaction.

### 2.5 `platform.integration` — Webhooks, Outbox Worker & Batch Engine ([ADR-013](file:///c:/Users/A275/Desktop/mini-ERP-main/docs/adr/ADR-013-platform-integration.md))
- **Signed Webhook Delivery & Secret Rotation**: Tenant-scoped endpoints (`/api/v1/integrations/webhooks`, `/api/v1/integrations/deliveries`) with HMAC-SHA256 payload signatures (`X-MiniERP-Signature`), dual-secret overlap rotation (`signing_secret` + `previous_signing_secret` / `previous_secret_expires_at`, with plaintext-at-rest documented as `VULN-06` Accepted Risk in `docs/security/threat-model.md`), `ROW_NUMBER()` fair cross-tenant `SKIP LOCKED` claims, exponential backoff retries, DLQ `DEAD` routing, and CLI worker (`app.cli.run_outbox_worker`).
- **DNS-Rebinding-Proof SSRF Defense**: Validates destination hosts against private/reserved/CGNAT/cloud-metadata IPv4/IPv6 ranges and dispatches via `_PinnedIPNetworkBackend` / `_PinnedAsyncHTTPTransport` (`trust_env=False`, strict port `443` / optional `80` allowlist, `Accept-Encoding: identity` + `aiter_raw()` byte caps).
- **CSV/JSON Batch Import & Export**: Master-data import (`POST /api/v1/integrations/imports` for `customer`, `product`, `account`) with per-row savepoint isolation, `dry_run` mode, and `custom_data` validation; entity export (`POST /api/v1/integrations/exports` across 8 registered entity adapters) with hardened OWASP CSV formula-injection neutralization, audited in `integration_batch_jobs` (`/api/v1/integrations/jobs`) and `app.cli.manage_integrations`.

## 3. Breaking Changes vs. `v0.1.0`

1. **Mandatory Authentication & RBAC**: Requests to `/api/v1/*` without a valid bearer session token return `401 Unauthorized`; requests missing required `module.resource.action` permission return `403 Forbidden`. (Use `app.cli.bootstrap_admin` + `POST /auth/login` first.)
2. **CLI-Only Global Reference & Tenant Provisioning**: HTTP write endpoints for UoM, UoM conversions, currencies, exchange rates, and company creation have been removed (`404`/`405` on HTTP); operators use `python -m app.cli.manage_reference_data` and `python -m app.cli.manage_companies`.
3. **Runtime Validation Guardrails**: Enabling required `custom_fields` or active `workflow` definitions on a tenant causes non-compliant document writes or transitions to reject cleanly with `422 Unprocessable Entity` or `409 Conflict` instead of silently succeeding.
